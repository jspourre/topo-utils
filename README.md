# Welcome to your Expo app 👋

This is an [Expo](https://expo.dev) project created with [`create-expo-app`](https://www.npmjs.com/package/create-expo-app).

## Get started

1. Install dependencies
0.......
   ```bash
   npm install
   ```

2. Start the app

   ```bash
   npx expo start
   ```

In the output, you'll find options to open the app in a

- [development build](https://docs.expo.dev/develop/development-builds/introduction/)
- [Android emulator](https://docs.expo.dev/workflow/android-studio-emulator/)
- [iOS simulator](https://docs.expo.dev/workflow/ios-simulator/)
- [Expo Go](https://expo.dev/go), a limited sandbox for trying out app development with Expo

You can start developing by editing the files inside the **app** directory. This project uses [file-based routing](https://docs.expo.dev/router/introduction).

## Build

Builds run in the cloud with [EAS Build](https://docs.expo.dev/build/introduction/). The project is linked to
[`@jspourre/land-nav-toolkit`](https://expo.dev/accounts/jspourre/projects/land-nav-toolkit) through the
`extra.eas.projectId` field in `app.json`.

Log in once:

```bash
npx eas-cli login
```

### Build profiles

Three profiles are defined in `eas.json`:

| Profile | Output | Use it for |
| --- | --- | --- |
| `development` | Dev client, internal distribution | Debugging with the Metro bundler attached |
| `preview` | Android `.apk`, internal distribution | Installing directly on a test device |
| `production` | Store-ready build, auto-incremented version | Publishing to the stores |

### Test on a physical Android device

```bash
npx eas-cli build --platform android --profile preview
```

This produces an `.apk`. Open the build page printed by the command (or the
[builds dashboard](https://expo.dev/accounts/jspourre/projects/land-nav-toolkit/builds)) **from the phone itself**, download
the artifact and install it — Android will ask you to allow installing apps from unknown sources for your browser. The
signing keystore is generated and stored by EAS on the first build; there is nothing to configure locally.

### Building uncommitted work

By default EAS uploads the last git commit, so anything still in the working tree is silently left out. To build the files
as they are on disk, disable VCS for that run:

```bash
EAS_NO_VCS=1 npx eas-cli build --platform android --profile preview
```

Files matched by `.gitignore` (or an `.easignore`) are still excluded. Prefer committing first for anything you intend to
share or reproduce.

### Build an APK locally with Gradle

No EAS account, no upload, no queue — the whole build runs on this machine.

**Prerequisites**

- **JDK 17** (`java -version`). Newer JDKs are not supported by the Android Gradle Plugin used here.
- **Android SDK**, with `ANDROID_HOME` pointing at it (or an `sdk.dir=` line in `android/local.properties`).
  Installing Android Studio is the simplest way to get it; the command-line tools alone are enough.
- Gradle itself does **not** need to be installed: the project ships a wrapper (`android/gradlew`, Gradle 9.3.1)
  that downloads the right version on first run.
- The `android/` directory. It is generated by prebuild and **git-ignored**, so a fresh clone has to recreate it:

  ```bash
  npx expo prebuild --platform android
  ```

**Debug APK** — fast to build, but it loads the JavaScript from Metro, so it only runs with `npx expo start`
on the same network:

```bash
cd android
./gradlew assembleDebug
```

Output: `android/app/build/outputs/apk/debug/app-debug.apk`

**Release APK** — self-contained, the JavaScript bundle and assets are baked in. This is the one to sideload:

```bash
cd android
./gradlew assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release.apk`

Install it on a plugged-in device with `adb install -r <path-to-apk>`, or just copy the file to the phone and
open it.

`npx expo run:android --variant release` does the same build and installs it in one step; the Gradle commands
above are useful when you only want the artifact, or when you need Gradle's own flags (`--info`, `--stacktrace`).

**About signing.** `android/app/build.gradle` signs the `release` build type with the **debug** keystore that
ships with the project. That is fine for installing on your own devices, but such an APK cannot be published to
a store and is not a trusted build. For a real key, generate one and point the release signing config at it:

```bash
keytool -genkey -v -keystore land-nav-toolkit.keystore -alias land-nav-toolkit \
  -keyalg RSA -keysize 2048 -validity 10000
```

then set `MYAPP_RELEASE_STORE_FILE`, `MYAPP_RELEASE_KEY_ALIAS` and the two passwords in
`android/gradle.properties` and replace `signingConfig signingConfigs.debug` in the `release` block — see the
[React Native signing guide](https://reactnative.dev/docs/signed-apk-android). Keep the keystore and its
passwords out of the repository.

**Two traps to know about**

- `android/` is git-ignored and regenerated by `npx expo prebuild --clean`: anything edited by hand in there
  (including a signing config) is lost. `app.json` is the source of truth for native configuration.
- On WSL2, `adb` does not see a phone plugged into the Windows host. Either use the Windows `adb.exe` on the
  produced file, or share the USB device with `usbipd`.

### iOS

`app.json` has no `ios.bundleIdentifier` yet, and installing on a physical iPhone requires a paid Apple Developer
account. Both are prerequisites before `--platform ios` will work.

## Get a fresh project

When you're ready, run:

```bash
npm run reset-project
```

This command will move the starter code to the **app-example** directory and create a blank **app** directory where you can start developing.
